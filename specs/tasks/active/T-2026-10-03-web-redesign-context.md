## T-2026-10-03-web-redesign-context — Сохранить контекст и иерархию при переносе Web UX

- Created: 2026-10-03
- Owner: Codex (Web)
- Status: ready
- Blockers: —
- Spec: maintainer request, 2026-10-03 — правила List/Board, URL, детей вне фильтра, прогресса и общей семантики Web/TUI утверждены; [proposal](../../../docs/proposals/2026-10-03-web-ux-redesign.md)
- Plan: none; the steps below are the whole change

### Goal

Пользователь переключает режим, открывает детали и раскрывает детей без потери контекста и без неявного изменения сохранённого представления. Прогресс и операции согласованы с core и TUI. Эта задача определяет перенос поведения; остальные экраны и тема переносятся отдельными задачами.

### Scenarios

1. **Given** сохранённый list view, **When** выбрать Board и перезагрузить страницу, **Then** тот же фильтр и Board восстановлены, сохранённый view.layout остаётся list; Back/Forward восстанавливают предыдущие экраны.
2. **Given** фильтр и режим, **When** открыть ребёнка, перейти к родителю и закрыть детали, **Then** контекст фильтра и режима сохранён; фокус возвращается к исходному доступному элементу.
3. **Given** родитель в фильтре и дети внутри/вне фильтра, **When** раскрыть родителя, **Then** видны все живые прямые дети; исключённые помечены, счётчик фильтра неизменен, дубликатов нет.
4. **Given** ребёнок в фильтре, родитель вне него, **When** открыть список, **Then** ребёнок виден в своём проекте со ссылкой на родителя.
5. **Given** повторяющийся родитель со скрытыми детьми, **When** завершить ребёнка и выполнить Undo, **Then** прогресс меняется на соответствующей оси вхождения и совпадает в list, board, details и TUI.
6. **Given** offline или отказ операции, **When** изменить ребёнка, **Then** локально принятая запись видна с очередью; отказ сохраняет ввод и причину; повтор намерения не создаёт новую операцию.

### Requirements

Все правила ниже утверждены пользователем 2026-10-03.

- **FR-001** Web MUST переключать List/Kanban/Calendar локально для текущего контекста в одной группе иконок справа вверху верхней панели страницы, сохраняя фильтр, sort и данные задач. Calendar — равноправный третий режим, без отдельного рабочего входа или дублирующей группы (уточнение пользователя 2026-10-03). Сохранённый view меняется только явным сохранением через существующую форму/операцию.
- **FR-002** Web MUST хранить контекст фильтра и режима в URL, восстанавливать его при reload и Back/Forward. Существующая идентичность view сохраняется в маршруте; локальный override кодируется query `layout=list|kanban|calendar`. Без override используется сохранённый layout. Невалидный override безопасно игнорируется. Переключение режима создаёт запись истории; нормализация URL использует replace.
- **FR-003** Web MUST сохранять прочие query-параметры при открытии/закрытии drawer через существующий `task` query. Закрытие не должно увести на другой фильтр/режим. После закрытия фокус возвращается к инициатору, а после его исчезновения — к ближайшему доступному элементу списка/доски или заголовку рабочей области.
- **FR-004** Web MUST раскрывать всех живых прямых детей родителя, включая завершённых и исключённых фильтром, явно обозначая контекстных детей вне результата. Они не добавляются к счётчику фильтра. Совпавший ребёнок показывается один раз; при исключённом родителе он остаётся самостоятельным со ссылкой на родителя и собственной принадлежностью проекту.
- **FR-005** Web MUST брать полный прогресс из `Item.subtasks`; checklist — из `taskDetails`. Не вычислять полный прогресс по отфильтрованному списку. Закрытие done/skipped, окончание серии и ось вхождения следуют core и ADR 0009. UI не переименовывает число closed в число только done.
- **FR-006** Web MUST использовать общие core операции завершения, Undo, перемещения и reparent с их отказами, settled/version и occurrence semantics. Родитель и ребёнок завершаются независимо; проект подставляется при создании ребёнка, дальнейшие изменения не каскадируются.
- **FR-007** Web MUST сохранять локально принятую offline-запись и очередь, удерживать ввод при отказе и повторять одно намерение без нового opId. EN/RU, keyboard/focus и доступные названия контролов входят в контракт.
- **FR-008** Проверка интеграции MUST подтвердить одинаковые фильтры, прогресс, завершение и Undo на общей реплике Web/TUI; разные способы управления и отсутствие layout override в TUI v1 допустимы.

### Edge cases

- Неизвестный/deleted task в URL → доступное сообщение, сохранённый контекст и рабочий Close (FR-003, T002).
- Fold, closed child, другой проект ребёнка → без двойного счёта; прогресс по всем живым детям (FR-004–005, T003).
- Recurring parent, skipped child, завершённая серия → checklist и прогресс следуют core, без boolean fixture (FR-005–006, T003–T004).
- Отказ reparent/Undo или несинхронизированная запись → причина видна, данные не подменены оптимистической fixture-копией (FR-006–007, T004).
- Нет override после смены view → новый view использует свой default layout; старый восстанавливается Back (FR-001–002, T002).

### Steps

- [ ] T001 [FR-001–008] Сверить исходные контракты и владельцев: `apps/web`, `packages/client-core/src/operations.ts`, TUI spec, ADR 0009. Зафиксировать способ чтения всех детей: `taskDetails` даёт ID/title/closed, дополнительные поля нужны из core projection, не из HTML fixture. При необходимости отдельной общей правки назначить одного владельца; TUI-файлы не менять в Web-задаче.
- [ ] T002 [FR-001–003, FR-007] Добавить failing-first route/history/focus проверки, затем реализовать transient layout и drawer context; проверить URL без override, invalid override, reload, Back/Forward, смену view и исчезновение инициатора.
- [ ] T003 [FR-004–005] Добавить failing-first проверки children/progress, затем реализовать раскрытие через core details/projections, принадлежность проекту, метки вне фильтра и уникальный счётчик. Не дублировать engine в Web.
- [ ] T004 [FR-006–008] Проверить операции и общую реплику: создать parent/child → list/board/details → изменить ребёнка → progress → Undo → исключить родителя фильтром → offline → sync; дополнительно recurring occurrence и refused reparent. Отчёт о соответствии TUI spec не заменяет фактический межклиентский прогон.
- [ ] T005 [FR-001–008] Выполнить Web/core tests, typecheck/build, lint и браузерные e2e; проверить i18n/CSP и обновить docs/статус с фактическими результатами. Fixtures не засчитывать как application integration.
- **Checkpoint:** правила реализованы и проверены в приложении; пока создана только спецификация, код и тесты не менялись.

### Open questions

Продуктовые правила утверждены. Точные projection/topic wiring и минимальные файлы реализации определяются в T001 по актуальному core; новые публичные контракты согласуются с их владельцем до изменения.
